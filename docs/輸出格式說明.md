# 輸出格式說明

LongBench v1（`longbench_eval.py`）與 v2（`longbench_v2_eval.py`）的 JSON 輸出格式說明。

---

## 頂層結構

```json
{
    "task": "narrativeqa",
    "version": "v1",
    "args": { ... },
    "results": { ... },
    "details": [ ... ]
}
```

---

## `results` 欄位

| 欄位 | 說明 |
|------|------|
| `avg_score` / `avg_accuracy` | 平均分數，**排除 OOM samples** |
| `num_oom` | OOM 發生次數（prefill + decode OOM 合計）|
| `avg_end_to_end_latency_ms` | 平均端到端延遲，**排除 OOM samples**（prefill + decode 都需有值才納入）|
| `avg_prefill_latency_ms` | 平均 prefill 延遲，**排除 OOM samples**（decode OOM 時 prefill 有值，會納入）|
| `avg_decode_latency_ms` | 平均 decode 延遲，**排除 OOM samples** |
| `max_peak_memory_mb` | 所有 samples 的最大峰值記憶體（含 OOM samples，OOM 時填 49152 MB） |

---

## `details` 欄位（每個 sample）

| 欄位 | 正常 | OOM(prefill) | OOM(decode) |
|------|------|--------------|-------------|
| `output` | 模型輸出文字 | `"OOM(prefill)"` | `"OOM(decode)"` |
| `score` | 0.0 ~ 1.0 | `0.0` | `0.0` |
| `prefill_latency_ms` | 有值 | `null` | 有值 |
| `decode_latency_ms` | 有值 | `null` | `null` |
| `end_to_end_latency_ms` | 有值 | `null` | `null` |
| `peak_memory_mb` | 實測值 | `49152.0` | `49152.0` |

> `49152.0 MB = 48 GiB`，為 A6000 的 VRAM 上限。

---

## OOM 終端輸出

發生 OOM 時會透過 `tqdm.write()` 在 progress bar 上方即時輸出：

```
OOM(prefill) at sample 3, with 131055 tokens.
OOM(decode) at sample 7, with 98432 tokens.
```

---

## 注意事項

- `avg_score` 排除 OOM samples，使分數不被 0 分拉低
- `avg_prefill_latency_ms` 在 decode OOM 的情況下仍會納入該 sample 的 prefill 時間
- OOM 原因通常是 128K context window（131072 tokens）下輸入過長，prefill OOM 比 decode OOM 更常見
